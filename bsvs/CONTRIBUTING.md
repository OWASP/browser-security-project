# Contributing

## Introduction

The OWASP Browser Security Verification Standard (BSVS) is a community-driven project. We welcome contributions from security practitioners, browser vendors, enterprise IT teams, and anyone interested in improving browser security.

## How can I help?

### Review existing requirements

The most valuable thing you can do right now is review the current controls and ask:

- Is this requirement independently testable? Can an auditor verify it with specific evidence?
- Is the scope clear? Could this control be confused with a control in a different chapter?
- Is anything missing? Are there browser security concerns that are not covered?
- Is anything duplicated? Do two controls in the same or different chapters say the same thing?

If you find issues, please open a GitHub issue first before submitting a pull request.

### Other ways to contribute

- **Propose missing controls**: If you know of a concrete, testable requirement that belongs in the standard, propose it.
- **Improve requirement clarity**: If a requirement is ambiguous or hard to test, suggest improvements.
- **Add references**: Each chapter should reference relevant standards, benchmarks, and research.
- **Fill in mappings**: Help map requirements to ATT&CK/ATLAS, CWE, CIS Benchmarks, and NIST CSF.

### Process

1. [Open an issue](https://github.com/OWASP/browser-security-project/issues) describing your proposed change
2. Discuss with the community and project leaders
3. If asked, [submit a pull request](https://github.com/OWASP/browser-security-project/pulls) with your changes

## AI-Assisted Contributions

AI tools are welcome as a productivity aid. Every contribution must reflect the contributor's own security judgment. Requirements must be concrete and testable — vague or generic text will not be accepted regardless of how it was produced.
